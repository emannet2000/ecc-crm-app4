# Focused staff workflows

Daily work is the home screen. Pipeline charts and the activity heatmap are now
in Reports. Role navigation presents each primary task once; all other modules
remain accessible. Deals, offline work and existing records are preserved pending
staff usage evidence. Optional AI briefs are expandable; the AI launcher is
available only when workspace capabilities report AI enabled. No voice feature
has been activated by this change.

## Manager exception queue

Managers and administrators see the existing priority component on Home, focused
on unassigned active work, missing action plans, stalled applications and overdue
pending handoffs. Reports and Workspace tools retain the full priority queues.
Manager-only queues and counts are excluded from ordinary staff responses.
Every result respects workspace and record visibility and links to its record.

Stalled means at least 14 calendar days since the latest recorded stage event.
Creation/opening date is used only when no stage history exists, and the result
labels that fallback. This is a review signal, not a claim that an application is
late. Accepted, cancelled and declined handoffs do not enter the overdue queue;
the current owner remains responsible until acceptance.

## One application action plan

The inline next-action editor is in Application essentials with responsible
staff, due date and the document requirements. The duplicate plan in Record tools
is removed. Full application editing remains available for ownership and other
fields. Lead work keeps its own plan editor without another copy in Record tools.
Application links lead to documents, communication, student journey and the
client's financial timeline. Missing, expired, rejected and awaiting-review
documents use the existing specific issue descriptions and action links.

## Service templates

Managers create service templates in **Workspace tools → Workflows**. Enter the
service category, required documents, suggested supported stages, starting action
and optional deadline in days. An empty service applies to any service. A scoped
template must match the application's service. The application form previews the
checklist, suggested stages and defaults before saving.

Applying a template adds missing document names without replacing files or
creating duplicate requirements. Selecting **Fill missing next action and
deadline** uses the defaults only for empty fields. Existing action plans stay
intact. Suggested stages are guidance; stage changes still use the existing
supported stages, permissions and gates. Shared follow-up messages can also carry
a service label so staff can select the relevant starting message and review it.
No service-specific requirements are assumed without staff configuring them.

## Communication and operational attention

Communication history combines incoming/outgoing conversation messages and
queued email, with pagination after access filtering. It shows the linked client,
application or invoice, delivery status and available error details. Unreadable
application/invoice associations and other workspaces are excluded. SMTP `sent`
means provider acceptance; it does not claim delivery to the recipient's inbox.
Uncertain delivery requires checking provider evidence before retrying.

Unconfigured email and WhatsApp do not offer send controls. History remains
available, and setup instructions point to Integrations. Payment-link controls
are offered only when payment configuration is reported available. Existing
server-side access and integration checks continue to enforce each request.

Managers see Operational attention on Home and in Work priorities: workspace
failed/waiting/uncertain email, WhatsApp problems, failed webhooks, connection
status and backup health. Recent delivery items link directly to their records.
Backup monitoring reads beside the active database; manager summaries expose
status and verification state without backup paths. Administrators retain full
backup/restore details and configuration. No live integration acceptance or
successful backup is inferred from configuration alone.

Use the staff session worksheet to decide whether optional modules should be
retired and to identify the next three task-completion fixes. No records or
modules have been deleted in this cycle.

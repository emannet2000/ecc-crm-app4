# First staff usability sessions

Status: prepared; actual sessions and findings pending.

Run one 20-minute session with an adviser and one with finance staff. A receiving
adviser is also needed for the handoff task. Use their normal accounts in a test
workspace. Do not coach unless asked; record any help you provide.

## Prepare

- Prepare a new referral lead with a harmless sample CV and a named referrer.
- Choose a test student with an application, a missing document and a portal reply.
- Give the application a meaningful next action and an overdue test deadline.
- Pick two similarly named test contacts and a record beyond the first list page.
- Prepare an unpaid test invoice. Use a manually recorded test receipt; no provider
  credentials or live payment are needed for this session.
- Ensure the receiving adviser already has access to the test application.
- Have a phone available for one task. Keep customer data out of observations.

## Opening script — 2 minutes

“We’re checking how easy the app is to use. Please say what you’re looking for
and what you expect to happen. If you get stuck, tell me. We’re testing the app,
not your ability.”

## Adviser tasks — 15 minutes

1. “Find the application you would work on first today. Explain why and what
   you would do next.” Allow 4 minutes.
2. “Find this test student, review the missing document and portal reply, then
   update the next action.” Allow 5 minutes. Supply the chosen student's name.
3. “Hand this application to the receiving adviser. Explain who is responsible
   while they review the request, then have them accept it.” Allow 6 minutes.

If no receiving adviser is available, test the proposal and mark acceptance as
not tested. Do not count an administrator impersonating a participant as a staff
session.

## Lead intake follow-up — 10 minutes

Run this as a separate adviser task so the first session remains 20 minutes:

“Find the new referral inquiry, review its sample CV, record the next action,
and convert it into a student/application. Then find the original attachment
and explain which staff member owns the application.” Allow 7 minutes.

Check that the chosen lead, referrer, attachment and ownership remain associated
with the resulting records. Record any hesitation, duplicate creation or lost
context. Allow 3 minutes for the adviser to repeat finding the application and
attachment on a phone. Use another test lead if repeating conversion.

## Finance tasks — 15 minutes

1. “Find the correct test student and application among similarly named records.
   Create an invoice for 150 in the workspace's currency.” Allow 6 minutes.
2. “Record a test receipt for 50. Explain the remaining balance and whether the
   payment needs approval.” Allow 5 minutes.

   If testing approval, select **Request manager approval** and ask a manager to
   review it in **Balance and receipt approvals**. Before approval, the receipt
   must remain outside the posted balance; after approval it should reduce it by
   50. Record whether staff understand that distinction.
3. “On a phone, find the same invoice and check its payment history.” Allow
   4 minutes. Do not make another payment.

## Closing questions — 3 minutes

- Where did you hesitate or need help?
- Which label or control did you expect to find?
- What would most improve this task in your everyday work?

## Observation record

Before starting, record the session date, app version or commit, participant role,
device/browser and test record references. Use anonymous participant labels such
as Adviser A and Finance A; do not include names, credentials or customer data.

Count a task as completed only when its intended result is saved and the
participant can explain it. Record help separately even if the task succeeds.
If the allotted time expires, record the task as not completed and capture where
the participant stopped. Mark tasks that were never attempted as **Not tested**
in this worksheet; do not submit them as failed observations in the app.

## Fix and retest

For each obstacle, capture role, task, steps, expected behavior and actual behavior.
Fix blocked tasks first, then repeated delays. Record the change and ask the same
role to repeat the affected task. Report actual staff observations separately
from automated checks. Do not mark these sessions complete until participants
have performed the tasks.

Use one issue per reproducible obstacle. Classify it as **Blocked** if the task
cannot be completed, **Needs help** if completion requires coaching, or **Delay**
if the participant completes it independently but repeatedly hesitates or retries.
Prioritize blocked tasks, then obstacles seen across participants, then isolated
delays. Time limits help run the session; they are not production performance
targets.

For each retest, use the same role and comparable test data, record a new
observation, and link it to the issue. A fix is validated when the participant
completes the affected task without the original obstacle. Record remaining help
or new obstacles instead of treating a passing automated test as staff acceptance.
